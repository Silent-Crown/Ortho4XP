<objective>
**User story:** **As a** scenery scripter, **I want to** get a clear, specific error when
an ICAO lookup is unreachable or the code is unknown — and see the full 3x3 tile block for
a valid ICAO — **so that** a script never silently builds the wrong tile.

Expansion of the Plan 01 tracer: complete BUILD-01's three-way failure classification
(unreachable / ICAO-unknown / DB-unavailable — all non-zero exit, distinct messages, never
a silent wrong coordinate) and grow `report coverage` from the containing tile to the full
containing+8-neighbor block (D-11) with the shared built/partial/missing vocabulary.

Purpose: satisfy D-04's exact "distinguish unreachable from unknown" contract and D-11's
neighbor semantics.
Output: the finished resolver error taxonomy and the finished `report coverage` command.

**RESEARCH deviation reminder:** the server returns `isError:false` even for not-found —
classify on the inner `code`/`error` fields, never on `isError`.
</objective>

| T-02-07 | Info disclosure | error messages | low | mitigate | Messages are specific but not leaky (server URL + code + short reason); no full traceback to the user for the two known failures (single-line stderr). |
| T-02-02 | Tampering | untrusted server payload | medium | mitigate | Coordinate finite/in-range validation before flooring (carried from Plan 01). |
| T-02-01 | Denial of Service | resolver HTTP | medium | mitigate | Explicit timeout retained; one attempt, fail fast (D-04). |
