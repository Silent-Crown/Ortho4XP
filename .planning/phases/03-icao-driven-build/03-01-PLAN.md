<objective>
**User story:** As a scenery-builder, **I want to** name ICAOs (one, a comma list, or a file)
instead of computing lat/lon by hand, **so that** the right tiles get built unattended.

Extend the existing `build` subcommand with `--icao`, `--icao-file`, and `--radius`,
spending the Phase 2 resolver (`O4_ICAO_Utils.resolve_icao`) and the Phase 1
`run_build` pipeline. Resolve each ICAO to its containing tile, optionally expand to a
Chebyshev radius, dedupe into a unique sorted tile set, build each once, and summarize
with a binary exit code. Build orchestration only — no changes to the resolver, report
commands, or build-pipeline algorithms.

Purpose: deliver BUILD-02..05 so users can script scenery generation by airport code.
Output: new flags + three functions in `src/O4_CLI_Utils.py`, a new test file
`tests/test_build_icao.py`, and updated `dispatch`.
</objective>

**New CLI flags on the existing `build` subparser:**
- `--icao` (comma-separated ICAO code list)
- `--icao-file` (path to a newline-delimited ICAO list file)
- `--radius` (int, default 0; Chebyshev radius in whole tiles)

**Changed argparse surface:**
- `build` positionals `lat` / `lon` become optional (`nargs="?"`, default None) so an ICAO
  source can stand in for them. `--icao` and `--icao-file` sit in an argparse
  mutually-exclusive group.

**New functions in `src/O4_CLI_Utils.py`:**
- `neighbor_tiles(lat, lon, radius=0)` — returns the deduped, (lat,lon)-sorted list of
  Chebyshev-square tiles with antimeridian wrap + pole skip.
- `parse_icao_args(icao, icao_file)` — resolves the flags into a list of ICAO idents
  (comma split or file read; blank/`#` lines ignored; clean exit on unreadable file).
- `run_batch_build(idents, radius, provider, zl)` — the batch orchestrator (resolve all →
  assemble unique tile set → build each → summarize → binary exit).
- `_validate_build(parser, args)` — cross-field usage validation (exactly one source;
  `--radius` requires an ICAO source), calling `parser.error()` (exit 2).

**New dispatch branch:** `build` with an ICAO source routes to `run_batch_build`; the bare
positional `lat lon` path still routes to `run_build` (unchanged).

**New test file:** `tests/test_build_icao.py`.

**No new `O4_*.py` module** — per CONTEXT Claude's-Discretion, the generator/parser/
orchestrator live in `O4_CLI_Utils.py` next to `run_build`/`dispatch` (reuse over a new
file). No new runtime dependency (stdlib `argparse` + existing `requests` only).
